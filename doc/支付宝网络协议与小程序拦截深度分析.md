# 支付宝网络协议与小程序拦截深度分析报告

> 涵盖：ARiver (NebulaX) 引擎、HttpWorker 传输层、RPC 拦截机制及防 OOM 存储方案

> 分析日期: 2026-05-09

## 一、 小程序流量核心：ARiver (NebulaX) 传输层 ⭐⭐⭐⭐⭐

这是目前支付宝小程序（my.request）流量的最核心入口，取代了陈旧的 H5NetworkUtil。

### 1.1 TransportServiceImpl - 传输服务实现类

**组件信息:**
- 类名: `com.alipay.mobile.nebulax.integration.mpaas.proxy.impl.TransportServiceImpl`
- 职责: 现代小程序网络请求的总调度中心。

**关键方法:**
```java
// 核心抓包点：捕获所有小程序 HTTP 请求
RVHttpResponse httpRequest(RVHttpRequest request)

// 下载抓包点：捕获小程序文件下载
void addDownload(RVDownloadRequest request, RVDownloadCallback callback)
```

**逆向数据结构分析:**
1. **RVHttpRequest**:
    - `getUrl()`: 获取完整请求地址。
    - `getMethod()`: GET/POST 等。
    - `getHeaders()`: 提取请求头（包含关键的 AppID 信息）。
    - `getRequestData()`: 返回 `byte[]`，即请求原始 Body。
2. **RVHttpResponse**:
    - `getStatusCode()`: 状态码。
    - `getHeaders()`: 响应头。
    - `getResStream()`: **关键！** 这是一个 `InputStream`。直接读取会导致主程序无法处理数据，必须使用“镜像分流”技术（如 Sesame 的 `CaptureInputStream`）进行非破坏性读取。

## 二、 支付宝底层传输引擎：HttpWorker ⭐⭐⭐⭐

这是支付宝所有业务（包括传统 H5、部分 RPC、文件上传）的通用传输层。

### 2.1 HttpWorker - 通用网络执行器

**组件信息:**
- 类名: `com.alipay.mobile.common.transport.http.HttpWorker`
- 职责: 封装 Apache HttpClient，处理网络连接、重试及响应分发。

**关键方法:**
```java
// 核心抓包点：捕获请求处理结果
Response handleResponse(HttpUrlRequest request, HttpResponse response, int code, String msg)
```

**逆向数据结构分析:**
1. **HttpUrlRequest**:
    - `getUrl()`: 获取 URL。
    - `getHeaders()`: 获取 `ArrayList<Header>`。
    - `getReqData()` / `mReqData`: 获取 POST 原始字节。
2. **HttpResponse (Apache)**:
    - 标准的 Apache HTTP 响应对象，通过 `getEntity().getContent()` 或 `mResData` 提取结果。

## 三、 高级 RPC 拦截潜力分析 (研究中) ⭐⭐⭐

RPC 是支付宝自定义的加密二进制协议（通常基于 Protobuf）。

### 3.1 MpaasRemoteRpcServiceImpl - RPC 服务实现

**组件信息:**
- 类名: `com.alipay.mobile.nebulax.integration.mpaas.proxy.impl.rpc.MpaasRemoteRpcServiceImpl`

**利用点:**
- **`addRpcInterceptor(Class, RpcInterceptor)`**: 
    - 这是一个极其强大的功能。通过注入全局 RPC 拦截器，可以在请求被加密/签名之前拦截到原始的 Java 对象或 Protobuf 数据。
    - 相比在网络层抓包（只能看到乱码），在这里拦截可以直接看到业务明文。

## 四、 工业级抓包：防 OOM 与存储逻辑 ⭐⭐⭐⭐⭐

针对支付宝这种内存消耗极高的应用，Sesame 采用了一套名为“分级溢出”的存储方案。

### 4.1 镜像分流技术 (CaptureInputStream)
- **原理**: 继承 `FilterInputStream`，在 `read()` 过程中同步将数据写入缓冲区。
- **内存优化**: 
    - 数据 < 1MB：保留在 `ByteArrayOutputStream`。
    - 数据 > 1MB：自动激活磁盘缓冲，开启 `FileOutputStream` 写入临时文件。
    - **结果**: 彻底解决了捕获 10MB+ 大文件（如高清图片、资源包）导致的 `java.lang.OutOfMemoryError`。

### 4.2 分离式存储策略 (CaptureStorage)
- **索引文件 (`.jsonl`)**: 只存储元数据（URL、Header、状态码等）和超短 Body。
- **独立 Body 仓 (`/bodies/`)**: 超过 512KB 的 Body 会被自动“剥离”到独立文件存储，索引中仅记录文件 ID。
- **按需加载**: UI 列表加载时只读索引，极速响应；点击详情时才通过 ID 捞取 Body，极大降低了应用内存水位。

## 五、 常用 AppId 与 场景参考

在小程序拦截中，通过 Header 中的 `Referer` 或 `X-Target-AppId` 可以识别具体业务：
- `60000002`: 蚂蚁森林
- `66666674`: 芭芭农场
- `68687809`: 蚂蚁庄园
- `20000067`: 收钱码

## 结论

本报告梳理了支付宝目前最先进的网络协议架构。**ARiver 传输层**是抓取现代小程序流量的“银弹”，而 **HttpWorker** 则是保障全量覆盖的最后一道防线。配合 **CaptureInputStream 的磁盘缓冲技术**，Sesame 已具备在极端流量环境下保持稳定抓包的能力。
