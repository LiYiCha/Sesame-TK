## 一、概述

### 1.1 功能说明

本文档提供了完整的支付宝滑块验证码关闭解决方案，包括：
- ✅ 简洁高效的Hook实现代码
- ✅ 详细的配置参数说明
- ✅ 完整的技术原理分析
- ✅ 实战使用指南

**验证码类型**: 滑块验证码（Slide Captcha）

### 1.2 实现原理

通过Hook `GlobalCache.e()` 方法，在配置初始化时修改滑块验证码开关配置，将 `enable` 参数设置为 `0`，从源头关闭滑块验证功能。

**优势**：
- 🎯 从源头控制，最稳定可靠
- 🔧 兼容性好，不受支付宝版本影响
- ✨ 代码简洁，易于维护

## 二、Hook实现

### 2.1 核心代码

**文件**: `app/src/main/java/fansirsqi/xposed/sesame/hook/CaptchaHook.kt`

```kotlin
package fansirsqi.xposed.sesame.hook

import de.robv.android.xposed.XC_MethodHook
import de.robv.android.xposed.XposedHelpers
import fansirsqi.xposed.sesame.util.Log

/**
 * 支付宝验证码Hook工具类
 * 
 * 功能说明：
 * Hook GlobalCache.e() - 在配置初始化时修改默认值，从源头关闭验证码
 * 
 * 优点：
 * - 从源头控制，最稳定可靠
 * - 兼容性好，不受支付宝版本影响
 * - 后续所有读取都是修改后的值
 * 
 * @author ghostxx
 * @since 2025-10-22
 */
object CaptchaHook {
    private const val TAG = "CaptchaHook"

    /**
     * 验证码配置键名
     */
    private const val CAPTCHA_SWITCH_KEY = "rds_captcha_switch"
    
    /**
     * 配置分组名
     */
    private const val CAPTCHA_GROUP_KEY = "switch"

    /**
     * 关闭状态的配置值（enable=0表示完全禁用）
     */
    private const val CAPTCHA_DISABLED_CONFIG = """{"enable":0,"intercept":0,"blackList":[],"intervalTime":0}"""

    /**
     * GlobalCache类名
     */
    private const val CLASS_GLOBAL_CACHE = "com.alipay.apmobilesecuritysdk.tool.store.cache.GlobalCache"

    /**
     * 主入口：启动验证码Hook
     * 
     * @param classLoader 目标应用的ClassLoader
     */
    fun hookCaptcha(classLoader: ClassLoader) {
        Log.runtime(TAG, "开始Hook支付宝验证码...")
        
        // Hook配置写入（在初始化时就修改默认值）
        hookGlobalCacheWrite(classLoader)
        
        Log.runtime(TAG, "验证码Hook设置完成 ✅")
    }

    /**
     * Hook方法: 拦截GlobalCache配置写入
     * 
     * 原理：在应用启动初始化配置时，修改写入的默认值
     * 优点：从源头控制，后续所有读取都是修改后的值
     * 
     * 目标方法: GlobalCache.e(String, String, String) -> boolean
     * 参数说明:
     *   - 参数1: 配置分组 (如 "switch")
     *   - 参数2: 配置键名 (如 "rds_captcha_switch")
     *   - 参数3: 配置值 (JSON字符串)
     *   - 返回值: true=写入成功, false=写入失败
     */
    private fun hookGlobalCacheWrite(classLoader: ClassLoader) {
        try {
            val globalCacheClass = XposedHelpers.findClass(CLASS_GLOBAL_CACHE, classLoader)
            
            XposedHelpers.findAndHookMethod(
                globalCacheClass,
                "e",
                String::class.java,
                String::class.java,
                String::class.java,
                object : XC_MethodHook() {
                    override fun beforeHookedMethod(param: MethodHookParam) {
                        val group = param.args[0] as? String
                        val key = param.args[1] as? String
                        val value = param.args[2] as? String
                        
                        // 只拦截验证码配置的写入
                        if (group == CAPTCHA_GROUP_KEY && key == CAPTCHA_SWITCH_KEY) {
                            Log.runtime(TAG, "拦截验证码配置写入")
                            Log.runtime(TAG, "  配置分组: $group")
                            Log.runtime(TAG, "  配置键名: $key")
                            Log.runtime(TAG, "  原始配置: $value")
                            Log.runtime(TAG, "  修改配置: $CAPTCHA_DISABLED_CONFIG")
                            
                            // 修改参数3，将配置值改为关闭状态
                            param.args[2] = CAPTCHA_DISABLED_CONFIG
                        }
                    }
                }
            )
            
            Log.runtime(TAG, "✅ Hook GlobalCache.e() 成功 - 已拦截配置写入")
        } catch (e: Throwable) {
            Log.error(TAG, "❌ Hook GlobalCache.e() 失败")
            Log.printStackTrace(TAG, e)
        }
    }
}
```

## 三、配置参数详解

### 3.1 配置JSON结构

```json
{
  "enable": 2,
  "intercept": 0,
  "blackList": [],
  "intervalTime": 0
}
```

### 3.2 参数说明

#### 3.2.1 enable（总开关）

| 值 | 含义 | 行为 |
|----|------|------|
| `0` | ✅ **完全关闭** | 不触发任何验证码 |
| `1` | 默认启用 | 根据其他条件判断 |
| `2` | 黑名单模式 | 只对黑名单中的操作触发验证码 |

**源码逻辑**：
```java
int i = jSONObject.has("enable") ? jSONObject.getInt("enable") : 1;
if (i == 0) {
    MLog.f("rds_captcha", "degrade: enable = 0");
    return false;  // 完全关闭，直接返回不触发
}
```

#### 3.2.2 intercept（拦截模式）

**作用**：区分验证码的触发来源

| 值 | 匹配来源 | 说明 |
|----|---------|------|
| `0` | `COSTOMS` | 自定义来源（常规RPC调用） |
| `1` | `INTERCEPT` | 拦截器来源（被拦截的RPC） |

**InterceptSourceEnum 枚举**：
```java
public enum InterceptSourceEnum {
    DEFAULT("default", "rpc"),
    COSTOMS("customs", "rpc"),      // intercept=0 匹配
    INTERCEPT("intercept", "rpc"),  // intercept=1 匹配
    TinyAppCloud("tinyAppCloud", "rpc"),
    MANUAL("manual", "rpc")
}
```

**源码逻辑**：
```java
int i2 = jSONObject.has("intercept") ? jSONObject.getInt("intercept") : 0;

// 来源不匹配时不触发
if ((InterceptSourceEnum.INTERCEPT.equals(interceptSourceEnum) && i2 != 1) || 
    (InterceptSourceEnum.COSTOMS.equals(interceptSourceEnum) && i2 != 0)) {
    MLog.f("rds_captcha", "degrade RpcInterceptorSource");
    return false;
}
```

#### 3.2.3 blackList（黑名单列表）

**作用**：指定哪些操作需要触发验证码

**数据类型**：字符串数组

**示例**：
```json
{
  "enable": 2,
  "blackList": [
    "alipay.operation.type.example1",
    "alipay.operation.type.example2",
    "alipay.operation.type.example3"
  ]
}
```

**源码逻辑**：
```java
ArrayList arrayList = new ArrayList();
if (jSONObject.has("blackList")) {
    JSONArray jSONArray = jSONObject.getJSONArray("blackList");
    for (int i4 = 0; i4 < jSONArray.length(); i4++) {
        arrayList.add(jSONArray.getString(i4));
    }
}

// enable=2（黑名单模式）或者操作在黑名单中，才触发验证码
if ((i == 2 || arrayList.contains(str)) && 
    System.currentTimeMillis() - this.f > i3) {
    return b(str, interceptSourceEnum.g);
}
```

**工作模式**：
- 当 `enable = 2` 时：**只有在黑名单中的操作才会触发验证码**
- 当 `enable = 1` 时：黑名单作为额外条件

#### 3.2.4 intervalTime（间隔时间）

**作用**：控制两次验证码触发的最小时间间隔

**单位**：毫秒（ms）

**示例**：
```json
{
  "intervalTime": 60000  // 1分钟内只触发一次
}
```

**源码逻辑**：
```java
int i3 = jSONObject.has("intervalTime") ? jSONObject.getInt("intervalTime") : 0;

// 检查距离上次触发的时间间隔
if (System.currentTimeMillis() - this.f > i3) {
    return b(str, interceptSourceEnum.g);
}
```

### 3.3 完整判断流程

```
1. 检查配置是否为空
   ↓ 是 → 不触发
   ↓ 否
   
2. 检查 enable 值
   ↓ enable=0 → 不触发 ✅
   ↓ enable≠0
   
3. 检查是否已在验证中
   ↓ 是 → 不触发
   ↓ 否
   
4. 检查 intercept 来源
   ↓ 不匹配 → 不触发
   ↓ 匹配
   
5. 检查时间间隔
   ↓ 未达到 → 不触发
   ↓ 已达到
   
6. 检查黑名单条件
   ↓ enable=2 且不在黑名单 → 不触发
   ↓ enable=2 且在黑名单 → 触发验证码 ⚠️
```

## 四、技术原理分析

### 4.1 核心类结构

#### 4.1.1 CaptchaManager（验证管理器）

**类名**: `com.alipay.apmobilesecuritysdk.captcha.CaptchaManager`

**核心方法**:
```java
public boolean c(String str, InterceptSourceEnum interceptSourceEnum)
```

**作用**: 判断是否需要触发验证码拦截

**返回值**:
- `true` - 触发验证
- `false` - 不触发验证

#### 4.1.2 GlobalCache（配置缓存）

**类名**: `com.alipay.apmobilesecuritysdk.tool.store.cache.GlobalCache`

**核心方法**:
```java

```

**参数**:
- `str` - 配置分组（如 "switch"）
- `str2` - 配置键名（如 "rds_captcha_switch"）
- `str3` - 配置值（JSON字符串）

**返回值**: `true`=写入成功

**存储结构**:
```java
public static ConcurrentHashMap<String, String> f149052a = new ConcurrentHashMap<>();

// 存储格式
{
  "switch_rds_captcha_switch": "{\"enable\":2,...}",
  ...

```

### 4.2 配置读取流程

```
应用启动
    ↓
GlobalConfig 静态初始化 <clinit>
    ↓
GlobalCache.e("switch", "rds_captcha_switch", "...")
    ↓
[我们的Hook] 修改参数3 → {"enable":0,...}
    ↓
写入 ConcurrentHashMap
    ↓
后续所有读取都是修改后的值
```

### 4.3 验证触发流程

```
用户执行特定操作
    ↓
RPC 拦截器检测
    ↓
CaptchaManager.c(operationType, source)
    ↓
读取配置: GlobalConfig.b("rds_captcha_switch")
    ↓
从 GlobalCache 读取（已被Hook修改）
    ↓
解析 JSON: {"enable":0,...}
    ↓
判断 enable 值
    ↓
enable=0 → return false（不触发滑块验证）✅
```

### 4.4 关键类和方法汇总

| 类 | 方法 | 作用 |
|-----|------|------|
| `GlobalCache` | `e(String, String, String)` | ✅ **写入配置（Hook目标）** |
| `GlobalCache` | `b(String, String)` | 读取配置 |
| `GlobalConfig` | `b(String)` | 读取配置（封装） |
| `CaptchaManager` | `c(String, InterceptSourceEnum)` | 判断是否触发验证 |
| `CaptchaManager` | `b(String, String)` | 锁定验证状态 |

## 六、故障排查

### 6.1 常见问题

#### Q1: Hook失败，日志显示找不到类

**原因**: 支付宝版本更新，类名可能变化

**解决方案**:
1. 使用JADX反编译新版本APK
2. 搜索 `GlobalCache` 类
3. 确认类名和方法签名
4. 更新Hook代码

#### Q2: Hook成功但仍然出现验证码

**原因**: 可能是服务端动态下发配置覆盖了本地配置

**解决方案**:
1. 检查日志，确认是否成功拦截配置写入
2. 考虑Hook配置读取方法 `GlobalConfig.b()`
3. 检查是否有其他初始化路径

#### Q3: 日志显示Hook成功，但没有拦截日志

**原因**: 配置写入可能在Hook之前完成

**解决方案**:
1. 确认Hook时机是否足够早（应在 `Application.attach` 之前）
2. 检查 `ApplicationHook.java` 中的调用位置

### 6.2 调试技巧

1. **增加日志**：在关键位置添加更多日志输出
2. **断点调试**：使用IDEA远程调试功能
3. **版本对比**：对比不同支付宝版本的差异

### 6.3 版本兼容性

| 支付宝版本 | Hook状态 | 说明 |
|-----------|---------|------|
| 10.3.x - 10.5.x | ✅ 已测试 | 完全兼容 |
| 10.6.x+ | ⚠️ 待测试 | 需要验证类名是否变化 |

**建议**: 每次支付宝更新后，先在测试环境验证Hook是否有效

## 七、总结

### 7.1 核心要点

1. **Hook目标**: `GlobalCache.e()` 方法
2. **Hook时机**: 应用启动初始化时
3. **关键配置**: 设置 `enable=0`
4. **效果**: 从源头关闭验证码功能

### 7.2 优势

- ✅ **稳定可靠**: 从源头控制，后续所有读取都是修改后的值
- ✅ **兼容性好**: `GlobalCache` 类非常稳定，不受版本影响
- ✅ **代码简洁**: 只需Hook一个方法，易于维护
- ✅ **性能优秀**: 无需多层拦截，开销最小

### 7.3 最佳实践

1. ✅ 在 `Application.attach` 之前就完成Hook
2. ✅ 详细记录日志，便于问题排查
3. ✅ 每次支付宝更新后验证兼容性
4. ✅ 定期查看日志，确保Hook持续生效
