# 核心编码准则：谋定而后动，拒绝试错

为了确保生成代码的高质量和严谨性，在处理 Android 或任何项目源码时，必须严格遵守以下原则：

1. **拒绝“试错驱动开发”**
   禁止凭空捏造长路径名、包名或资源引用（例如 `com.google.android.material.R.attr.colorPrimary`）。
   不能抱有“先写上去，如果编译报错再回来修”的侥幸心理，必须在下笔的那一刻保证代码是合法且存在的。

2. **写前强制溯源与查证**
   在调用任何不熟悉或有歧义的方法、资源 ID、扩展函数时，必须先在当前项目中通过 `grep_search` 或文件阅读，寻找已有的、正确的使用范例（照猫画虎）。

3. **强制上下文对齐 (Imports 校验)**
   在任何文件中添加新类库的使用前，必须优先阅读该文件的头部 `import` 声明，确认是否需要手动补全导入，或者是否应采用当前文件已有命名空间的资源（例如本地优先的 `R.attr.*`）。

4. **一次写对**
   所有的逻辑推演和上下文调研必须在实际调用文件写入工具前完成。你的目标是：提交出的每一行代码都能无缝通过静态和编译检查。
